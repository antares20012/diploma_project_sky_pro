# Автоматизированное тестирование GitHub

**"Автоматизированное тестирование GitHub"** позволяет автоматически проверить 
основные пользовательские сценарии по работе с репозиториями и файлами на самой популярной платформе 
управления версиями и совместной разработке GitHub.

  - Результаты выполнения тестов, оформленные в багтрекинговой системе Ежка


## Особенности

### ✨ Ключевые возможности
* ⚙️ **Автоматизация:** Полностью автономная работа без участия пользователя.
* 📊 **Экспорт данных:** Отчет выводится при помощи Allure report

## Стек технологий

- **Язык:** Python 3.10 
- **Тестирование UI:** Selenium WebDriver
- **Тестирование API:** Requests (мощная библиотека для HTTP-запросов и валидации ответов)
- **Паттерны проектирования:** Page Object Model (POM)
- **Отчетность:** Allure Report

## Быстрый старт

### Требования

Для запуска проекта вам понадобятся:
- Git
- Тестовая учетная запись GitHub, если все таки не получится обойти защиту
- Token авторизации на GitHub
- Язык программирования проекта (например, Python 3.10+)
- Браузеры (Chrome, Firefox) или WebDriver
- Утилита Allure командной строки (для просмотра отчетов локально)


### Установка и запуск

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/antares20012/diploma_project_sky_pro
   cd diploma_project_sky_pro
   ```

2. **Установите зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

3. **Настройте переменные окружения:**
   ```bash
   cp .env.example .env
   ```
   *Откройте файл `.env` и укажите ваш токен и учетные данные.*

4. **Запустите тесты:**

   * Запуск всех тестов в headless-режиме:
     ```bash
     pytest --alluredir=allure-results
     ```
   * Запуск только UI-тестов:
     ```bash
     pytest -m ui --alluredir=allure-results
     ```
   * Запуск только API-тестов:
     ```bash
     pytest -m api --alluredir=allure-results
     ```

5. **Просмотр отчета Allure:**
   ```bash
   allure serve allure-results
   ```

💡 **Архитектура API-тестов:**  
> Все API-тесты строятся на базе библиотеки **Requests**. Класс `GitPageApi.py` инкапсулирует логику отправки базовых HTTP-методов (GET, POST, DELETE, PATCH) и автоматическую передачу авторизационного токена `GITHUB_TOKEN`. Класс `github_api_client.py` предоставляет высокоуровневые методы для работы с сущностями GitHub, что исключает дублирование кода в самих тестах.


🖥️ **Архитектура UI-тестов:**  
> UI-тесты реализованы с использованием **Selenium WebDriver** и паттерна **Page Object Model (POM)**. Класс `GitPageUI.py` инкапсулирует в себе локаторы элементов интерфейса GitHub и методы взаимодействия с ними (клики, ввод текста, ожидания). Это изолирует логику страниц от самих тест-кейсов: при изменении верстки сайта достаточно обновить класс страницы, не меняя логику тестов. При запускe UI-тестов используется headless-режим браузера для ускорения выполнения в CI/CD.

## Порядок заполнения `.env` файла

```dotenv
# Креденшелы для UI-тестов
LOGIN=your_username_here
PASSWORD=your_password_here

# Токен для API-тестов (Personal Access Token)
# Сгенерируйте в Settings -> Developer Settings -> Personal access tokens
GITHUB_TOKEN=ghp_your_personal_access_token_here
```
